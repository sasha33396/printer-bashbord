# Сборщик OCS + AD

Сборщик получает ПК, ноутбуки и мониторы из OCS, проверяет пользователя в Active Directory и передаёт нормализованные записи в приложение. Python 3.10+ использует стандартную библиотеку: устанавливать пакеты через pip не требуется.

Запускать на Windows под учётной записью с правом чтения AD. Нужны Windows PowerShell 5.1 и модуль RSAT ActiveDirectory — тот же, с которым уже проверяли `Get-ADUser`. Домен проверяется через `Get-ADDomain`; настройки и список полей соответствуют [документации Microsoft](https://learn.microsoft.com/en-us/powershell/module/activedirectory/get-aduser). Маршруты OCS описаны в [документации OCS](https://wiki.ocsinventory-ng.org/11.Rest-API/GET-Routes/).

## Первая проверка без обращения к приложению

В PowerShell из корня репозитория:

```powershell
Copy-Item tools/ocs_ad/config.example.json tools/ocs_ad/config.json
python tools/ocs_ad/collector.py --computer-id 94 --collect-only
```

Если Python запускается через `py`, можно заменить `python` на `py -3`. Перед повторным копированием проверьте, что не перезаписываете уже настроенный `config.json`.

Пример уже содержит адреса:

- OCS: `http://172.16.10.122/ocsapi/v1`;
- приложение: `http://172.16.51.73:3000` (nginx пересылает `/api/` в backend);
- AD: домен `ruskon.local`, контроллер `Server1.ruskon.local`.

В результате появится папка `tools/ocs_ad/output/<время-UTC>-<идентификатор>/`:

- `requests.json` — массив готовых запросов к API;
- `report.json` — результаты проверки, причины пропуска, конфликты и ответы приложения.

Режим `--collect-only` читает OCS и AD, сохраняет файлы локально. Он не требует токена и не отправляет запросы в приложение. Для просмотра результата:

```powershell
$run = Get-ChildItem tools/ocs_ad/output -Directory | Sort-Object Name -Descending | Select-Object -First 1
Get-Content (Join-Path $run.FullName 'requests.json') -Raw -Encoding UTF8
Get-Content (Join-Path $run.FullName 'report.json') -Raw -Encoding UTF8
```

## Настройки

`config.json` и каталог отчётов исключены из Git. Пароли и токены в конфигурации не хранятся.

| Поле | Назначение |
|---|---|
| `ocs_url` | Корень API OCS, включая `/ocsapi/v1` |
| `app_url` | Адрес приложения, прямого API или адрес с окончанием `/api` |
| `ad_server` | DNS-имя домена или конкретного контроллера |
| `ad_domain` | Ожидаемый DNSRoot AD; фактический домен проверяется |
| `ocs_timezone` | Часовой пояс `hardware.LASTDATE`, когда в ответе нет смещения |
| `source_key` | Постоянный идентификатор этого экземпляра OCS, например `main` |
| `max_age_days` | Максимальный возраст инвентаризации, по умолчанию 30 дней |
| `batch_size` | Записей в запросе, от 1 до 500, по умолчанию 200 |
| `http_timeout_seconds` | Таймаут одного HTTP-запроса |
| `ad_timeout_seconds` | Таймаут всего пакета запросов AD |
| `import_token_env` | Имя переменной окружения с токеном приложения |
| `output_directory` | Каталог результатов, относительно файла конфигурации |
| `excluded_logins` | Служебные логины, которые пропускаются |
| `laptop_names` | Подтверждённый список имён ноутбуков |

В примере `ocs_timezone` задан как `+04:00`. До применения сравните `LASTDATE` с временем последней инвентаризации в OCS: если база хранит UTC, задайте `UTC`. Часовой пояс компьютера сборщика автоматически не используется. Уже указанное смещение в ответе OCS сохраняется. Отсутствующая или неверная дата приводит к пропуску с ошибкой, а не замене текущим временем.

В Apache OCS доступ `/ocsapi` должен быть разрешён IP компьютера сборщика. Проверенный API использует ограничение по IP; поддержка других схем авторизации OCS в этой версии не добавлена.

## Токен и предварительная проверка импорта

На сервере приложения создайте отдельный токен, например:

```bash
openssl rand -hex 32
```

Запишите его в существующий `.env` приложения:

```dotenv
OCS_AD_IMPORT_TOKEN=полученный_токен
```

Пересоздайте backend, чтобы он прочитал переменную:

```bash
sudo docker compose up -d --no-deps --force-recreate api
```

На Windows задайте тот же токен в текущем PowerShell:

```powershell
$env:OCS_AD_IMPORT_TOKEN = 'тот_же_токен'
python tools/ocs_ad/collector.py --computer-id 94
```

Без `--apply` запросы всегда содержат `dry_run: true`. Backend проверяет сопоставления и возвращает предполагаемые действия, затем откатывает изменения. Филиал и отдел сборщик не выдумывает.

Для нескольких устройств:

```powershell
python tools/ocs_ad/collector.py --computer-id 94 --computer-id 121
```

Для всего OCS, сначала с ограничением:

```powershell
python tools/ocs_ad/collector.py --all --limit 10
python tools/ocs_ad/collector.py --all
```

## Применение

После проверки отчёта и резервной копии базы:

```powershell
python tools/ocs_ad/collector.py --computer-id 94 --apply
```

Затем повторите команду и проверьте отсутствие дублей. Режим применения заново читает OCS и AD: сохранённые предварительные ID не используются как подтверждение сопоставления.

```powershell
python tools/ocs_ad/collector.py --all --apply
```

После сетевой ошибки POST запрос автоматически не повторяется: применение могло уже завершиться на сервере. В отчёте сохраняются результаты предыдущих пакетов и `pending_batch` для пакета с неподтверждённым результатом. Сначала проверьте приложение. Ошибки OCS отдельных устройств не мешают проверке остальных; недоступность всего AD останавливает отправку.

## Преобразование характеристик

- `hardware` и `bios` поддерживаются как массивы и одиночные объекты. Пустой ключ JSON и строка с вложенным JSON не мешают разбору.
- ОЗУ из `hardware.MEMORY` и суммарный объём физических дисков из `storages.DISKSIZE` переводятся из МБ в ГБ, с округлением до ближайшего целого. Разделы из `drives` не суммируются повторно, оптические и съёмные устройства исключаются.
- `Fixed hard disk media` не считается доказательством HDD. Если SSD/HDD нельзя определить, тип накопителя остаётся пустым.
- Процессор, видеокарта, ОС, производитель, модель и серийник передаются отдельными полями.
- Для IP и MAC выбирается действующий физический сетевой адаптер; виртуальные, фильтры и отключённые адаптеры исключаются. При отсутствии подходящего адаптера допустим только проверенный `hardware.IPADDR`, без выдуманного MAC.
- Подтверждённые имена ноутбуков имеют приоритет. `bios.TYPE` Portable, Laptop, Notebook и другие поддержанные переносные корпуса также выбирают `laptop`. Неизвестный корпус не принуждает существующую карточку к категории ПК.
- Мониторы передаются с ID OCS, моделью, производителем и серийником. Backend пропускает новые мониторы без достоверного серийного номера с предупреждением. Диагональ по названию модели не угадывается.
- Короткий логин, `DOMAIN\login` и UPN проверяются в AD. Локальный или чужой домен не подменяется настроенным доменом. Для UPN выполняется поиск по UserPrincipalName, для короткого логина — по SamAccountName.
- В файлы попадают только данные импорта. Списки программ, лицензионные ключи, полный ответ OCS и токены не сохраняются.

## Конфликты и коды завершения

Дубли устройства, серийника, монитора или сотрудника проверяются по всему запуску до разбиения на пакеты. Неоднозначные записи исключаются целиком. Это сохраняет правило одного рабочего места на сотрудника независимо от `batch_size`.

- `0`: запуск завершён; отдельные записи могут быть пропущены с объяснением.
- `1`: ошибка настройки, подключения, AD или отправки; смотрите отчёт.
- `2`: запуск завершён с конфликтами или ошибками отдельных записей.

Backend остаётся окончательным источником решений по созданию, обновлению и закреплению. Его конфликты и предупреждения доступны в `report.json` → `batches` → `result`.

## Регулярный запуск

После успешной ручной проверки создайте задачу Планировщика Windows под той же учётной записью с доступом к AD. Укажите полный путь к `python.exe`, скрипту и `config.json`. Аргументы:

```text
"C:\path\printer-bashbord\tools\ocs_ad\collector.py" --config "C:\path\printer-bashbord\tools\ocs_ad\config.json" --all
```

Сначала используйте режим проверки; добавьте `--apply`, когда импорт проверен. Токен должен быть доступен в окружении пользователя задачи: переменная `$env:...` из интерактивного окна сама по себе не сохраняется для будущих заданий. Можно задать пользовательскую переменную окружения Windows под учётной записью задачи. В настройках задачи выберите «Не запускать новый экземпляр», если предыдущий ещё выполняется. Задачу автоматически сборщик не создаёт.

## Проверки разработчика

Из корня репозитория:

```powershell
python -m unittest discover -s tools/ocs_ad/tests -v
```

Проверка реального контракта API требует зависимостей backend. Она запускается в контейнере с временной SQLite, без подключения к рабочей базе; остальные тесты используют только стандартную библиотеку.
