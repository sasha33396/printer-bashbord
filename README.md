# Printer Dashboard

Система учёта печатающей техники.

Backend поддерживает пакетный импорт компьютеров, мониторов, сотрудников и рабочих мест
из данных OCS Inventory и Active Directory. Есть режим проверки без изменений БД,
сопоставление по логину AD, отдельный токен интеграции и отчёт каждого запуска.
Филиал и отдел при импорте необязательны. Контракт API и правила сопоставления:
[Импорт OCS + AD](docs/ad-user-import.md).

Python-сборщик для Windows с PowerShell ActiveDirectory готов к запуску.
Инструкция по настройке, предварительной проверке и применению:
[Сборщик OCS + AD](tools/ocs_ad/README.md).

## Рабочие места

Раздел «Рабочие места» объединяет закреплённые за сотрудником компьютер, монитор, телефон и другое
поштучно учитываемое оборудование. Для рабочего места задаются филиал, отдел, помещение и состояние.
Одного сотрудника и одну единицу оборудования можно одновременно закрепить только за одним рабочим
местом.

Карточка рабочего места показывает сотрудника, текущее оборудование и историю его назначений.
При переносе рабочего места в другой филиал или отдел местоположение закреплённого оборудования
обновляется автоматически. После снятия оборудование возвращается на склад и остаётся в истории.
Для карточки можно распечатать этикетку со штрихкодом и открыть её сканированием в приложении.
В карточке закреплённого оборудования отображается ссылка на его текущее рабочее место.
Кнопка «Редактировать» у устройства в карточке рабочего места открывает общую форму
оборудования: название, инвентарный и серийный номера, состояние, характеристики, сеть,
ОС и примечание. После сохранения список обновляется, изменения попадают в историю
оборудования. Филиал, отдел и расположение закреплённого устройства задаются рабочим местом.
Фотографии оборудования можно просматривать, добавлять и удалять как в складской карточке,
так и из карточки рабочего места. Для вставки из буфера обмена скопируйте изображение,
нажмите область вставки в разделе «Фотографии» и нажмите Ctrl+V. Вставка доступна также
в карточках печатающей техники; действуют ограничения JPEG/PNG/WebP, 10 МБ и 10 фото.
Для рабочего места можно выбрать основное фото из
фотографий закреплённого оборудования. Выбор автоматически сбрасывается, если это
оборудование снять с рабочего места или удалить выбранную фотографию.

Сотрудники ведутся в разделе «Настройки → Сотрудники». Сотрудника, закреплённого за рабочим местом,
нельзя удалить, деактивировать или перенести в другой филиал/отдел, пока рабочее место не освобождено
или не перенесено. Телефоны доступны в складском справочнике как поштучно учитываемое оборудование.

## Склад

Раздел «Склад» открывается сводкой по категориям из макета: картриджи, мыши,
клавиатуры, мониторы, компьютеры и принтеры. Нажатие на категорию открывает её
подробную таблицу. Расходники учитываются по количеству, а мониторы и компьютеры —
поштучно с инвентарным и серийным номерами. Для них доступны характеристики
из макета: диагональ и цвет монитора, ОЗУ, процессор, видеокарта и накопитель ПК.
Принтеры не дублируются на складе: сводка использует существующие устройства,
их тип, счётчик и историю ремонтов.

Инвентарный номер вводится вручную с физической наклейки в формате `1-00001`.
Поле необязательно при создании и редактировании: можно сначала добавить оборудование,
расклеить этикетки, затем внести фактические номера. Создание карточек, Excel/OCS-импорт
и перезапуск API не присваивают номера автоматически. Заполненные номера проверяются
на формат и уникальность среди печатающей техники и складского оборудования, включая архив.
Фотографии доступны и без номера; изменение или очистка номера сохраняет фотографии.
После изменения номера ранее напечатанная этикетка больше не соответствует карточке.
Для очистки прежних номеров с сохранением 11 подтверждённых устройств есть
[инструкция и скрипт](docs/manual-inventory-numbering.md). Обновление приложения само по себе номера не очищает.

При создании позиции обязательно выбирается филиал из справочника и при
необходимости отдел этого филиала. В списке они образуют наименование склада;
остатки можно фильтровать по филиалу и отделу. Существующие позиции без локации
сохраняются и получают её при следующем редактировании.

Один артикул можно завести в нескольких филиалах: уникальность проверяется
в пределах конкретного филиала и отдела. В дальнейшем к этой модели можно
добавить перемещения между складами отдельной операцией.

Кнопки «Экспорт по инв. №» и «Импорт архива» на странице склада переносят
карточки с заполненными инвентарными номерами ZIP-архивом. Оборудование без номера
в этот архив не включается; полный бэкап состоит из файла БД и каталога фотографий.
Для каждой единицы создаётся каталог
`1-00001`, в котором находится `1-00001.txt` со всеми данными карточки и её
фотографии. TXT содержит читаемую сводку и служебный JSON-блок для обратного
импорта. Повторный импорт обновляет существующую карточку с тем же номером;
история операций импортируется при создании новой карточки.

В карточке устройства, поштучной складской позиции и рабочего места доступна печать
этикетки 50×40 мм со штрихкодом Code 128 и читаемым инвентарным номером. В штрихкоде
устройства или складского оборудования хранится сам инвентарный номер, например
`1-00038`. У рабочих мест нет инвентарного номера, поэтому для них сохраняется код
`PD-W-ID`. Ранее напечатанные коды `PD-D-ID` и `PD-I-ID` также поддерживаются.
Кнопка «Сканировать штрихкод»
принимает снимок с камеры телефона и открывает найденную карточку. Такой режим работает
по HTTP без прямого браузерного видеопотока. Поле ручного ввода также поддерживает
USB- и Bluetooth-сканеры, работающие как клавиатура.

Устройства поддерживают необязательный IP-адрес (IPv4 или IPv6). Его можно
указать при создании/редактировании и посмотреть в списке и карточке устройства.
В Excel-шаблон добавлена последняя колонка `IP-адрес`; старые файлы без неё
по-прежнему поддерживаются. Строки с некорректным IP пропускаются с описанием ошибки.
В карточке устройства доступны фотографии с теми же ограничениями и структурой
хранения, что и для складского оборудования. Фотографии устройств также входят
в общий ZIP-экспорт и восстанавливаются при импорте.
При запуске API колонка автоматически добавляется в существующую БД без удаления данных.
В карточке устройства кнопка «Обновить счётчик» читает общий счётчик Kyocera
через HTTP с IP-адреса, сохранённого у этого устройства. Поддерживается формат
Command Center RX, проверенный на ECOSYS M2040dn. Сервер API должен иметь доступ
к принтеру на порту 80. Значение и время успешного опроса сохраняются; при ошибке
остаётся последнее успешное показание. При смене IP показание сбрасывается.
Опрос выполняется по нажатию кнопки, без фонового расписания.
У ремонта есть состояния «В ремонте», «Завершён» и «Ремонт невозможен», реквизиты
задачи, даты передачи, возврата и подключения, место, необязательное ответственное
лицо и список выполненных работ. Итоговая стоимость рассчитывается по строкам работ.
К ремонту можно прикрепить один PDF-счёт размером до 20 МБ.
При завершении API получает счётчик с IP устройства или принимает введённое вручную
значение. Для каждого завершённого ремонта рассчитывается количество страниц,
напечатанных после предыдущего завершённого ремонта этого принтера. У первого ремонта
разница не указывается. Активный ремонт можно завершить отдельной кнопкой в истории.
Кнопка отчёта формирует текст по сохранённым данным, который можно скопировать,
скачать в TXT или распечатать.

## Быстрый старт

### 1. Настройка окружения

```bash
cp .env.example .env
```

Открыть `.env` и заполнить:

| Переменная | Описание |
|---|---|
| `ADMIN_LOGIN` | Логин администратора |
| `ADMIN_PASSWORD` | Пароль администратора |
| `SECRET_KEY` | Случайная строка для подписи JWT (например: `openssl rand -hex 32`) |
| `PHOTO_DIRECTORY_HOST` | Каталог на сервере для фотографий, например `./equipment_photos` или `/srv/printer-photos` |

Фотографии сохраняются вне контейнера по структуре
`PHOTO_DIRECTORY_HOST/1-00001/1-00001_0001.jpg`,
`PHOTO_DIRECTORY_HOST/1-00001/1-00001_0002.jpg` и далее. Поддерживаются JPEG,
PNG и WebP, до 10 фотографий размером не более 10 МБ на единицу оборудования.
У карточек без инвентарника используется собственная папка `unassigned-device-ID`
или `unassigned-warehouse_item-ID`. Очистка и последующий ввод номера переносят альбом
в соответствующую папку, сохраняя содержимое и выбранное фото рабочего места.
При переводе старых инвентарных номеров в новый формат каталог и имена файлов
переименовываются автоматически.
Для Docker Desktop на Windows внешний каталог можно указать, например,
`PHOTO_DIRECTORY_HOST=D:/printer-photos`.

### 2. Запуск

```bash
chmod +x start.sh && ./start.sh
```

### 3. Открыть в браузере

```
http://<IP_КОМПЬЮТЕРА>:3000
```

Работает с любого устройства в локальной сети (ПК, телефон, планшет).

## Узнать IP компьютера

В Windows выполните:

```powershell
ipconfig
```

Используйте IPv4-адрес активного Ethernet- или Wi-Fi-адаптера, а не адаптеров
`vEthernet`, WSL и Docker. Этот же адрес должен открываться с телефона. Для
стабильного доступа рекомендуется закрепить адрес компьютера в DHCP.

## Сервисы

| Сервис | Адрес |
|---|---|
| Фронтенд (nginx) | `http://<IP_КОМПЬЮТЕРА>:3000` |
| API (FastAPI) | `http://<IP_КОМПЬЮТЕРА>:8000` |
| Документация API | `http://<IP_КОМПЬЮТЕРА>:8000/docs` |

## Остановка

```bash
docker-compose down
```

Данные БД сохраняются в Docker volume `db_data` и не удаляются при остановке.
