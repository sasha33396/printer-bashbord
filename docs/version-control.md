# История версий и откат

Локальная папка подключена к репозиторию
`https://github.com/eltyshxw/printer-bashbord.git`, ветка **Interactive_map**.
Исходная точка GitHub на момент подключения — **`666cded`**.
Текущее состояние после подготовки демостенда, расширения картриджей и добавления
удаления зафиксировано отдельным локальным коммитом с меткой
**`checkpoint/2026-10-18-cartridges`**.

До настройки Git промежуточные коммиты в этой папке не создавались.
Предыдущие этапы работы нельзя выдавать за отдельные сохранённые версии кода.
Доступны исходная версия из GitHub, текущая контрольная точка и будущие коммиты.
Накопленные резервные копии SQLite остаются в `.cache/demo/before-*.db`.

## Проверить историю

На этом компьютере Git подготовлен в папке проекта. В PowerShell:

```powershell
$projectGit = '.\.cache\runtime\git\cmd\git.exe'
& $projectGit status
& $projectGit log --oneline --decorate -8
& $projectGit diff 666cded HEAD --stat
```

Если установлен обычный Git, используйте `git` вместо полного пути.
Локальные контрольные коммиты подписаны техническим автором
`Codex local checkpoint <codex@local.invalid>`. Глобальные настройки пользователя
не изменены. Отправка на GitHub отдельно не выполнялась.

## Контрольная копия кода и данных

```powershell
.\.cache\runtime\python\python.exe tools\create_checkpoint.py before-next-change
```

В `.snapshots/<дата-время>-before-next-change` появятся:

- `source.zip` — исходники без баз данных и локальных конфигураций;
- `demo-runtime.db` — согласованная резервная копия текущей локальной демобазы,
  полученная через SQLite Backup API и проверенная `integrity_check`;
- `demo-files.zip` — локальные фотографии, подложки карт и PDF-счета демостенда;
- `manifest.json` — время, метка и текущий Git-коммит, если он есть.

Зависимости, `.env`, настройки OCS/AD с доступами, `.git` и рабочие каталоги
кэша в `source.zip` не включаются. Файлы демостенда копируются отдельно;
для согласованного восстановления связей БД с файлами делайте контрольную копию
в отсутствие загрузок и удаления файлов. Рабочий сервер в этот бэкап не входит.

После первоначальной настройки в контрольной копии с меткой
`version-control-ready` также сохранён **`history.bundle`**: локальная копия
Git-истории, пригодная для восстановления репозитория без обращения к GitHub.

## Как выполнять откат

Git восстанавливает код; текущую SQLite-базу и фотографии он автоматически
не восстанавливает. По умолчанию при откате кода текущие данные сохраняются.
Перед откатом сделайте новую контрольную копию. При восстановлении базы остановите
демостенд, сохраните текущий файл и восстанавливайте БД вместе с соответствующими
фотографиями и счетами.

Для обычной отмены изменений предпочтителен новый коммит `git revert`:
история остаётся видна. Чтобы только посмотреть старую версию, можно открыть
отдельный `git worktree` на нужном коммите. Не запускайте старую версию против
единственного экземпляра актуальной БД: схема после обновлений может отличаться.

Для восстановления состояния по запросу укажите метку/коммит и отдельно,
нужно ли восстанавливать данные. Точка `666cded` возвращает код до наших локальных
изменений; метка `checkpoint/2026-10-18-cartridges` — текущее завершённое состояние.
