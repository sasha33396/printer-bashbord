# Публикация и запуск

Основная поставка содержит исходники и примеры настроек. Базы SQLite, фотографии,
счета, `.env`, локальные конфигурации интеграций и резервные копии исключены из Git
и не должны прикладываться к публикации.

## Первый рабочий запуск

1. Скопируйте `.env.example` в `.env` и задайте собственные `ADMIN_LOGIN`,
   `ADMIN_PASSWORD`, `SECRET_KEY`. Ключ можно создать командой
   `python -c "import secrets; print(secrets.token_hex(32))"`.
2. Выполните `docker compose up -d --build` (Docker Compose v2).
3. Откройте `http://<адрес-сервера>:3000` и войдите с заданными учётными данными.
4. Добавьте филиалы, отделы, оборудование и сотрудников через интерфейс или импорт.

На новой установке создаётся пустая база в томе `db_data`. Имеющийся том сохраняет
свои записи при обновлении. Демогенератор при рабочем запуске не вызывается.
Uvicorn в образе работает без наблюдения за файлами.

OCS/AD настраивается отдельно: адреса в `tools/ocs_ad/config.example.json`
вымышленные. Списки ноутбуков и сопоставлений по ID по умолчанию пусты.
Скопируйте пример в исключённый из Git `tools/ocs_ad/config.json` и укажите
собственные параметры; см. [инструкцию сборщика](../tools/ocs_ad/README.md).

## Необязательные тестовые данные

`start-demo.cmd`, `tools/run_demo.py` и `docker-compose.demo.yml` запускаются
отдельно и используют собственную базу. Для генерации отдельного файла:

```bash
python backend/seed_demo.py --output .cache/demo-extra/printer_dashboard.db
```

Генератор не перезаписывает существующие файлы и не выбирает рабочую базу из
`DATABASE_URL`. Подробнее: [Демостенд](demo.md).

## Отправка на GitHub

Локальный репозиторий уже связан с `https://github.com/eltyshxw/printer-bashbord.git`,
ветка `Interactive_map`. Перед отправкой просмотрите изменения:

```bash
git status
git diff --stat origin/Interactive_map..HEAD
git push origin Interactive_map
```

Последняя команда публикует коммиты и выполняется отдельно по решению владельца.
В Windows без установленного Git используйте `.cache/runtime/git/cmd/git.exe`.

Удалённые из текущей версии файлы остаются в старых Git-коммитах. Обычная отправка
ветки передаёт её историю, включая прежние базы и настройки. История локального
репозитория сохранена для отката. Для публикации только очищенных исходников
используйте ZIP текущей версии, который можно создать так:

```bash
git archive --format=zip --prefix=printer-dashboard/ --output=.cache/printer-dashboard-source.zip HEAD
```

ZIP не содержит `.git`, старых версий и локальных файлов. Для нового репозитория
можно распаковать его в отдельную папку и создать в ней новую Git-историю.

## Обновление существующего сервера

Перед обновлением сохраните рабочую SQLite-базу и каталоги фотографий и счетов.
Не заменяйте их демобазой. Затем в рабочей копии проекта:

```bash
git pull --ff-only
docker compose up -d --build api frontend
```

Существующий `.env` и том базы сохраняются. Схема обновляется при запуске API.
Если импорт раньше использовал встроенные имена ноутбуков или сопоставления OCS,
перед обновлением задайте их явно через `OCS_AD_LAPTOP_NAMES` и локальные поля
`laptop_names` / `computer_matches` конфигурации сборщика.
Для отката кода и данных используйте [инструкцию по контрольным копиям](version-control.md).
