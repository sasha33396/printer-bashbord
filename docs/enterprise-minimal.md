# Enterprise Minimal

Редизайн внедрён в существующий React/Vite/Ant Design frontend по
[заданию](design.md) и приложенным к нему визуальным ориентирам. Backend,
схемы данных, маршруты API, проверки и правила инвентарного учёта не менялись.

## Общая система оформления

- `frontend/src/theme.js`: единая тема Ant Design, цвета, шрифты, размеры,
  формы, карточки и компактные таблицы.
- `frontend/src/styles.css`: CSS-переменные, каркас приложения, сетки,
  адаптивность, выбранные строки, панели сведений, диаграммы и фотографии.
- `frontend/src/main.jsx`: тема, русская локализация Ant Design и Dayjs.
- `frontend/src/App.jsx`: фиксированное меню 212 px, сворачивание до 64 px,
  мобильное меню, пользователь, выход и действующий сканер штрихкодов.

Нейтральный фон `#F5F7FA`, белые поверхности, тёмная навигация `#17263C`,
синий акцент `#2563EB`, границы `#E2E8F0`. Inter используется при наличии
в системе; иначе применяется системный sans-serif. Внешние шрифты и новые
UI-библиотеки не загружаются.

## Общие компоненты

- `PageHeading`: заголовок, описание раздела и действующие операции.
- `KpiCards`: показатели, состояния загрузки и недоступного значения.
- `DistributionCard`: распределения в виде полос или кольцевой диаграммы;
  значения доступны также текстом.
- `RecordPanel`: существующая карточка справа при ширине от 1200 px,
  Drawer на меньших экранах. Выбор сохраняется в query-параметре `record`.
  Открытие не размонтирует таблицу и не сбрасывает её фильтры. Закрытие
  обновляет реестр. Отдельные адреса карточек продолжают работать.
- `FilterableTable`: прежние составные фильтры, tooltip для сокращённого
  текста, общая поверхность таблицы и сброс фильтров. В справочниках включён
  поиск по отображаемым значениям. Неконтролируемые таблицы используют
  `defaultPageSize`, поэтому переключение размера страницы работает.

## Значения и ограничения данных

Обзор считает устройства из реестра печатающей техники и поштучного складского
оборудования; количество картриджей и прочих расходников не прибавляется к
количеству устройств. Показатель «На складе» включает только поштучные позиции
без рабочего места со значением состояния «На складе». Это не оценка всего
оборудования, которое физически может находиться в складском помещении.

Сроки ЭЦП/МЧД берутся из вычисленного сервером `term_status`. Динамика по месяцам,
процентные изменения, несуществующие статусы ремонтов и декоративные кнопки
из макетов не добавляются. Сводка аналитики по ремонтам и активным принтерам
имеет фильтр периода и охватывает все филиалы; таблица затрат и её распределение
используют также фильтр филиала/отдела. Журнал движений имеет отдельные фильтры.

Карточки повторно используют существующие компоненты и обработчики. Например,
принтер перемещается только тем способом, который уже поддерживает приложение;
новые операции учёта ради макета не вводятся. У сотрудника не отображаются
фиктивные роли и привязки, отсутствующие в его ответе API.

При частичной ошибке загрузки обзор сохраняет доступные разделы, показывает
предупреждение и `—` вместо недоступного KPI. Основные реестры показывают
постоянную ошибку с повторным запросом. Большие таблицы прокручиваются внутри
своей области. Все существующие формы, подтверждения, импорт и экспорт,
сканирование, печать и фотографии сохраняют прежнюю бизнес-логику.

## Проверки

Из каталога `frontend`:

```powershell
npm.cmd test
npm.cmd run build
```

Для повторения браузерной проверки откройте два терминала в каталоге `frontend`:

```powershell
# Терминал 1
npm.cmd run dev -- --host 127.0.0.1 --port 4173 --strictPort
# Терминал 2
npm.cmd run test:ui
```

Нужны Node.js 22+ и Chrome/Chromium или Edge. При нестандартной установке
задайте `CHROME_BIN`. `UI_SMOKE_URL` позволяет выбрать другой локальный порт.
Скриншоты сохраняются в игнорируемом Git каталоге `.cache/redesign`.

Unit-тесты включают регрессии импорта, всех полей документов, ведущих нулей,
фильтров, расположений, ошибок фото и новых расчётов обзора.

Браузерная проверка использует headless Chrome и отдельные тестовые ответы API,
перехватываемые только внутри проверочного браузера. В код приложения
тестовые массивы не включены. Проверяются маршруты, карточки, открытие форм,
сохранение реквизитов и адаптивность. Реальная БД при этой проверке не изменяется.

Физическая камера, принтер этикеток, сетевой опрос принтера и реальные XLSX/ZIP/PDF
операции с рабочим backend требуют проверки в окружении эксплуатации.
Сборка может сообщать о крупном основном JS-бандле и устаревающем CJS API Vite;
это не ошибки компиляции.

Сетки обзора учитывают ширину рабочей области через CSS container queries:
открытие боковой карточки перестраивает блоки, даже если окно браузера остаётся
широким. Вложенные карточки ограничены своей колонкой, таблицы прокручиваются
внутри неё, длинное ФИО владельца сокращается с подсказкой. Браузерный сценарий
проверяет отсутствие наложения с длинными ФИО при открытии ЭЦП и МЧД из обзора
на desktop, планшете и телефоне. Для отдельного запуска этой регрессии:

```powershell
npm.cmd run test:ui -- --overview-only
```
